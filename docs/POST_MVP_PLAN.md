# politecrawl — POST_MVP_PLAN

Nice-to-have за рамками учебной цели MVP. Ничего из этого не требуется для
рабочего вежливого краулера — это направления для дальнейшего роста.

## JS-рендеринг через headless-браузер

Часть современных сайтов отдают контент только после исполнения JS. Опциональный
рендер-бэкенд (Playwright/`pyppeteer`) за общим интерфейсом `Fetcher`, чтобы
основной asyncio-путь оставался лёгким, а headless включался флагом
`--render` только там, где нужно. Дорого по ресурсам — поэтому строго опционально.

## Распределённый краулинг по нескольким машинам

Вынести фронтир и множество посещённых во внешнее общее хранилище (Redis:
очередь + `SET`/bloom для дедупа), чтобы несколько воркер-процессов/машин
обходили один граф совместно. Именно здесь **bloom filter** становится
оправдан (память на разделяемое множество URL при очень крупном обходе) — в
MVP он сознательно отклонён в пользу точного in-memory `set` (см.
TECHNICAL_PLAN §Этап 4).

## Экспорт результатов в разные форматы

Пока итог — текстовый отчёт в stdout. Добавить структурированный экспорт:
- граф ссылок в JSONL / CSV (ребро «страница → исходящая ссылка»);
- sitemap-подобный XML;
- дамп метаданных страниц (URL, статус, title, content-type).

## Прочие идеи

- Персистентность фронтира: возобновление прерванного обхода с чекпоинта.
- Уважение `Crawl-delay` и `Sitemap:` из `robots.txt`.
- Адаптивный per-domain rate-limit по времени отклика домена (авто-backoff на 429/5xx).
- Метрики Prometheus / структурные логи для наблюдаемости обхода.
