# politecrawl — PLAN

## Видение

**politecrawl** — вежливый структурный асинхронный веб-краулер. Учебный
pet-проект с фокусом на `asyncio`-конкурентности: как обходить множество
доменов параллельно, но при этом **вежливо** — уважая `robots.txt`, соблюдая
per-domain rate-limit, не дублируя URL и честно применяя backpressure к
медленным доменам.

Цель — не «ещё один скрейпер», а тренажёр для конкурентных паттернов. Ключевая
техническая изюминка: **per-domain rate-limiting без глобального throttling
всей очереди**. Наивный глобальный семафор сериализует весь обход и убивает
саму идею; правильное решение — лениво создаваемые семафоры по ключу (домену)
с корректным управлением жизненным циклом.

Инструмент — single-machine CLI без внешних сервисов (нет БД, нет брокера,
нет Docker). Вход: ограниченный список seed-URL + максимальная глубина.

## Верхнеуровневая архитектура

```
seed-URL(ы) ──▶ Frontier (очередь URL с глубиной)
                     │
                     ▼
             ┌─────────────────┐
             │   Crawler loop  │  N asyncio-воркеров
             └─────────────────┘
                     │
   для каждого URL:  │
   1. dedup: видели? ─── да ─▶ пропустить
   2. robots: можно? ── нет ─▶ пропустить
   3. ratelimit: занять слот домена (per-domain семафор) ── ждать, если занято
   4. fetch: httpx.AsyncClient GET
   5. extract_links ─▶ положить новые URL в Frontier (depth+1, если < max)
                     │
                     ▼
              Итоговый отчёт (посещено / пропущено / ошибки, разбивка по доменам)
```

Модули:

| Модуль | Ответственность |
|---|---|
| `fetcher` | async HTTP-загрузка + извлечение ссылок |
| `robots` | загрузка/парсинг/кеш `robots.txt` per-domain |
| `ratelimit` | per-domain семафоры (главная конкурентная задача) |
| `dedup` | нормализация URL + множество посещённых |
| `cli` | разбор аргументов, запуск обхода, отчёт |

## Этапы (MVP)

- **Этап 1** — базовый asyncio-краулер: fetch страниц + парсинг ссылок, без politeness.
- **Этап 2** — `robots.txt`: парсинг и per-domain кеширование правил.
- **Этап 3** — per-domain rate-limiting через лениво создаваемые семафоры (**главная тех-задача**, отдельный этап с усиленным тестовым покрытием).
- **Этап 4** — дедупликация URL: нормализация + множество посещённых.
- **Этап 5** — ограничение глубины обхода + CLI + итоговый отчёт.

Детальная разбивка — в [`TECHNICAL_PLAN.md`](TECHNICAL_PLAN.md).

## Явно вне скоупа MVP

- JS-рендеринг (headless browser) — режем полностью.
- Распределённый краулинг по нескольким машинам — только single-machine.
- Персистентность фронтира/состояния между запусками.
